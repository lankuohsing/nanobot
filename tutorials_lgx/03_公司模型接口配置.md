# 03：配置公司的模型 API

学习目标：让 nanobot 使用公司提供的 OpenAI Chat Completions 接口，分清 URL、Key、模型 ID 和协议，并完成第一条请求。本文所有接口和凭据示例都是占位符，真实值由读者在自己的本地配置填写。

## 1. 确认环境与学习实例

先按 [第 02 章](./02_首次运行.md) 安装源码、激活选定环境并完成 `onboard`。后续命令从自己的仓库根目录执行；进入新终端时重新激活环境并设置下面的路径变量。作者使用 Conda `py312`，新同事可使用自己的独立环境。

```bash
export LGX_NANOBOT_HOME="$PWD/tutorials_lgx/.runtime"
```

本章修改 `tutorials_lgx/.runtime/config.json`；新实例的默认 Agent 工作区为 `.runtime/workspace/`，整个 `.runtime/` 已被 Git 忽略。`export`、`--home` 与工作区的区别及初始化输出见 [第 02 章](./02_首次运行.md#2-初始化学习实例并配置模型)。完成初始化后直接配置模型，无需重复执行 `onboard`。

## 2. 手动填写公司 API 配置

接口协议、地址、凭据和模型 ID 是不同的信息：URL 确定请求发到哪里，Key 用于鉴权，模型 ID 决定服务端调用哪个模型，协议决定请求/响应格式。模型 ID 必须使用公司 API 文档中的真实值，不用预设名称代替。

| 公司给出的完整请求 URL | 应填写的 `apiBase` |
| --- | --- |
| `https://gateway.example.com/v1/chat/completions` | `https://gateway.example.com/v1` |
| `https://gateway.example.com/company/openai/v1/chat/completions` | `https://gateway.example.com/company/openai/v1` |
| `https://gateway.example.com/chat/completions` | `https://gateway.example.com` |

nanobot 将 `apiBase` 传给 OpenAI 客户端，由客户端追加 `/chat/completions`；它不自动补 `/v1`。保留公司的实际路径前缀，不把完整请求地址当作 `apiBase`。

可以直接用编辑器修改本地配置，URL、模型 ID 与 Key 都支持普通字符串，不需要先在命令行设置这三个值。把下列片段合并到已有 `.runtime/config.json`：新增 `providers.companyLlm` 和 `modelPresets.company`，并设置 `agents.defaults.modelPreset`；保留原来的 workspace、channels、tools 等设置。此片段不能替换整份配置。

```json
{
  "providers": {
    "companyLlm": {
      "apiBase": "https://gateway.example.com/v1",
      "apiKey": "REPLACE_WITH_COMPANY_API_KEY",
      "api": {
        "supportedApis": ["chat_completions"],
        "preferredApi": "chat_completions"
      }
    }
  },
  "modelPresets": {
    "company": {
      "provider": "companyLlm",
      "model": "REPLACE_WITH_COMPANY_MODEL_ID"
    }
  },
  "agents": {
    "defaults": {
      "modelPreset": "company"
    }
  }
}
```

`companyLlm` 是自定义连接名称，`company` 是模型预设名称，都由我们命名；`model` 才是发送给公司服务的模型 ID。显式引用 Provider 和协议能避免自动路由猜错，不需要新增 Provider 类或修改 Agent 核心。

替换下面三个值，其余名称可以保持不变。`apiKey` 填裸 Key，由客户端添加 `Authorization: Bearer ...`；学习笔记与提交的示例仍只放占位符。

| 字段 | 替换为 |
| --- | --- |
| `providers.companyLlm.apiBase` | 公司基础地址，按前面的 URL 表保留实际前缀 |
| `providers.companyLlm.apiKey` | 公司 Key，不加 `Bearer ` 前缀 |
| `modelPresets.company.model` | 公司提供的真实模型 ID |

在原有 `providers`、`modelPresets`、`agents.defaults` 对象内新增或修改字段，保留已生成的其他设置；不要创建同名的重复顶层键。配置文件使用标准 JSON，不写注释或末尾多余逗号。保存后再启动；后续手动编辑已运行实例的配置时，重启对应进程以确保重新加载。

温度、最大输出和上下文窗口修改在当前选中的 `modelPresets.company` 中；压缩触发与参数示例见 [第 07 章](./07_上下文压缩与模型参数.md)。

## 3. 可选：使用环境变量引用

也可以让配置只保存环境变量引用。将上面三个字段分别改成下表的字符串，再在启动 nanobot 的终端设置实际值；无需重复维护另一份 Provider 配置。

| 字段 | 配置中的字符串 |
| --- | --- |
| `providers.companyLlm.apiBase` | `"${COMPANY_LLM_API_BASE}"` |
| `providers.companyLlm.apiKey` | `"${COMPANY_LLM_API_KEY}"` |
| `modelPresets.company.model` | `"${COMPANY_LLM_MODEL}"` |

下面的 URL 与模型 ID 仍是占位示例，运行前替换；Key 输入命令适用于当前 zsh，不回显输入。

```bash
export COMPANY_LLM_API_BASE="https://gateway.example.com/v1"
export COMPANY_LLM_MODEL="REPLACE_WITH_COMPANY_MODEL_ID"
read -rs "COMPANY_LLM_API_KEY?请输入公司 API Key："
export COMPANY_LLM_API_KEY
```

新终端需要重新提供这些变量，已运行的进程不会获得后续 export 的值。`${VAR}` 不支持 shell 默认值语法，引用的变量缺失会导致配置加载错误。选择直接填写实际字符串时，跳过本节即可；`LGX_NANOBOT_HOME` 是选择实例路径的变量，与这些模型参数变量作用不同。

## 4. 检查配置与发起第一条请求

保持所选 Python 环境已激活、同一个 `LGX_NANOBOT_HOME` 已设置；选择环境变量方案时，还需提供上一节的变量。

```bash
# 仅检查本地配置，不调用模型
python -m nanobot --home "$LGX_NANOBOT_HOME" status

# 准备好后运行：会调用公司模型 API
python -m nanobot --home "$LGX_NANOBOT_HOME" agent \
  --session lgx:company-first -m "只回复：连接成功。"

# 后续体验浏览器时，继续使用同一实例和当前终端环境
python -m nanobot --home "$LGX_NANOBOT_HOME" webui \
  --yes --port 8766 --gateway-port 18792
```

新会话跟随默认预设 `company`；已有会话若保存过其他模型选择，需要用 `/model company` 切换。在 WebUI 中也可选择该预设。

status 应显示学习实例的配置和工作区、公司模型 ID，以及 `Agent: ✓ provider/model configuration is ready`；它只检查本地配置，不验证网络、鉴权或配额。实际收到助手回复才说明这次请求成功；回复措辞略有差异不等于连接失败。WebUI 的入口、端口与观察点见 [第 02 章](./02_首次运行.md#4-体验-webui观察状态归属)。

当前普通 Agent 请求使用流式输出，公司服务应支持标准 SSE，包括 `stream=true` 和 `stream_options.include_usage`。首次 `agent -m` 请求也会携带已启用的 `tools` 和 `tool_choice`，即使提示只要求一句回复，接口仍需接受这些字段；返回结构化 `tool_calls` 及接收 `role=tool` 结果的能力，还需后续真实工具实验单独验证。依据：[AgentRunner](../nanobot/agent/runner.py)、[OpenAI 兼容适配器](../nanobot/providers/openai_compat_provider.py)。

## 5. 常见提示与排查方向

| 现象 | 优先检查 |
| --- | --- |
| status 指向 `~/.nanobot` | 是否遗漏 `--home`，或新终端尚未设置学习路径变量 |
| Key 暂填 `xxx`，status 仍显示 ready | 非空占位符也可能通过本地配置检查；实际请求前换成真实 Key |
| `agents.defaults.model` 还保留旧模型 | 设置 `modelPreset` 后，当前模型来自对应预设；应检查 status 显示的有效模型 |
| 配置解析错误或变量缺失 | JSON 语法、字段值/模型预设引用及 `${VAR}` 所需变量；同时避免重复键导致字段被覆盖 |
| HTTP 401/403 | Key、鉴权格式、模型或账号权限；按公司网关返回信息确认 |
| HTTP 404 | 基础路径、是否重复追加 `/chat/completions`，以及模型 ID |
| HTTP 400、提示未知字段 | 网关是否接受流式参数及 `tools`、`tool_choice` 等实际请求字段 |
| 超时或流式中断 | 网络/代理、服务端 SSE 输出与连接保持情况 |
| `already inside a git repo; skipping nested repo initialization` | 工作区位于现有 Git 仓库内，跳过嵌套仓库创建；文件记忆仍可保存 |
| `zsh: command not found: 2.` | 可能把教程编号一并粘贴成了命令；只复制代码块中的命令 |

工作区 Git 提示的实现见 [GitStore.init](../nanobot/utils/gitstore.py)；跳过独立仓库时，没有该独立仓库提供的自动 Git 版本记录。排障记录只保留必要的脱敏错误信息。
