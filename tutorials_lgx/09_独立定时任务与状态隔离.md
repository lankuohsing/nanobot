# 09：独立定时任务与状态隔离

本项目要求每次任务从空历史开始，只使用固定角色、规则、技能与本次数据。完整的本地方案是：每次创建新的 home、配置、Agent 工作区、session 和进程，任务结束后保存结果并停止实例；下一次重新创建。这比仅换 session 或 WebUI 临时聊天更完整，因为它也隔离动态记忆、工作文件与运行状态。本文依据当前检出源码，版本基准见 [README](./README.md)。

本地手动调试可以直接使用原生命令，每次准备新 home 和工作区，无需启动脚本。[launch_isolated_task.py](./examples/launch_isolated_task.py)只是将重复准备、权限设置、实例核验与清理自动化，适合实验增多后使用。日常命令见 [第 05 章](./05_常用命令速查.md#4-每次独立任务)。

## 本地调试：不用脚本的最短流程

在仓库根目录、已激活 `py312` 的终端中，每次完整执行下面的准备步骤。现有的 `task_template/config.json` 是已经生成的干净模型配置模板；也可以自行维护一份只含模型连接与固定设置的配置。

```bash
LGX_TASK_HOME="$PWD/tutorials_lgx/.runtime/manual_runs/$(uuidgen)"
mkdir -p "$LGX_TASK_HOME"
cp tutorials_lgx/.runtime/task_template/config.json "$LGX_TASK_HOME/config.json"
```

CLI 与 WebUI 任选其一：

```bash
python -m nanobot --home "$LGX_TASK_HOME" agent \
  --workspace "$LGX_TASK_HOME/workspace" \
  -m "替换为本次任务描述与数据。"
```

```bash
python -m nanobot --home "$LGX_TASK_HOME" webui \
  --workspace "$LGX_TASK_HOME/workspace" \
  --yes --no-dock --port 8767 --gateway-port 18793
```

原生命令会补齐新工作区的默认角色与记忆文件，不需要每次再运行 onboard。新 home 中没有旧会话数据库，因此 CLI 可以继续使用默认 session 名，无需另外生成新 key。若希望使用已定制的固定角色与技能，只复制模板中的 `AGENTS.md`、`SOUL.md`、`USER.md` 和必要技能；不复制旧工作区、记忆或会话目录。

仅改变 `--home` 不会改写已有配置里的绝对工作区路径，也不会自动继承公司 API 配置。新 home 下需要自己的 `config.json`，启动时显式带上面的 `--workspace`，避免误用旧工作区；不要通过 `--config` 指回旧 home 的配置，因为运行数据跟随配置文件所在目录。

WebUI 启动前确认两个端口都空闲，使用本次默认工作区。任务结束后按 `Ctrl+C`，并用同一组选项明确停止网关；下一次重新生成 `LGX_TASK_HOME`：

```bash
python -m nanobot --home "$LGX_TASK_HOME" gateway stop \
  --workspace "$LGX_TASK_HOME/workspace"
```

这些步骤分开每项任务的本地历史、记忆与默认文件目录，旧记录可以保留。手动复制的模型模板没有自动应用脚本中的工具限制；若还要求工具无法读取其他任务目录，需要配置 `tools.restrictToWorkspace`，shell 另需沙箱，见第 5 节。新实例中的 Dream、Heartbeat 使用配置值；不需要它们时，可在固定配置模板中关闭，再复制到每项任务。

下面各节介绍可选脚本方案及更完整的权限与运行管理。

## 固定 home，只更换 Agent 工作区

本地串行调试可以保持同一个 home 和公司模型配置，每次把 `agents.defaults.workspace` 改为全新的目录，再启动运行。这不依赖先关闭长期记忆：`MemoryStore` 本身跟随 Agent 工作区，新工作区没有上次的记忆。这里更换的是全局 Agent 工作区，不是 WebUI 话题中的项目目录。

| 内容 | 固定 home、换全新 Agent 工作区后的情况 |
| --- | --- |
| `MEMORY.md`、`history.jsonl`、`SOUL.md`、`USER.md`、技能 | 使用新工作区自己的文件；只从固定模板复制角色与必要技能 |
| 会话消息、摘要和模型续接状态 | 使用新工作区标识对应的数据库：`home/sessions/<workspace-id>/sessions.sqlite3` |
| 本次输入与输出 | 放入本次工作区，并限制工具跨目录读写 |
| 上传文件、认证、缓存、日志与用量记录 | 仍可能共用配置文件旁的 home 级目录 |

当前没有统一的 `memory.enabled` 配置开关。`agents.defaults.dream.enabled=false` 只关闭后台记忆整理，普通持久会话仍会自动加载已有的 `MEMORY.md`；也不会清空聊天历史。每次新工作区时没有旧记忆可加载，仍可关闭 Dream 和 Heartbeat 来减少无关后台活动。

CLI 每次运行都会重新建立运行时，可以直接使用参数覆盖工作区，无需改写配置：

```bash
# 已按第 05 章激活环境、进入仓库并设置 LGX_NANOBOT_HOME
LGX_TASK_WORKSPACE="$LGX_NANOBOT_HOME/experiments/$(uuidgen)"
python -m nanobot --home "$LGX_NANOBOT_HOME" agent \
  --workspace "$LGX_TASK_WORKSPACE" -m "替换为本次任务描述与数据。"
```

WebUI 应先停止旧 Gateway，再修改配置中的 `agents.defaults.workspace` 并重新启动；编辑文件不会让已经运行的 Agent 自动重建。也可在新启动命令中指定 `--workspace`，WebUI 会保存这个值。若原启动命令带了显式 `--workspace`，停止旧 Gateway 时也须带原来的工作区参数。每次新工作区不复制旧 `memory/` 或 `.nanobot/workspace-id`，网页保持本次默认工作区和 Restricted 权限。

这适合主要使用文本和本次目录数据的调试。共享 home 的 `media/` 不会自动把旧上传塞进模型上下文，但它是 Restricted 文件工具的额外只读目录，仍可按路径读取；shell 和其他集成也需要自己的权限限制。如果要求连上传、缓存和实例运行状态的目录都完全分开，继续使用每次新 home 的方案。

## 两个脚本各做什么

[launch_isolated_task.py](./examples/launch_isolated_task.py)是启动准备助手：`init` 保存固定模板；每次创建新 home、配置、工作区和 session，复制本次数据，再调用原生 CLI / WebUI；结束或 `Ctrl+C` 时清理自己启动的进程。代码主要用于配置校验、复制规则、端口检查、实例身份核验和进程清理，没有金融决策逻辑。

[test_isolated_task.py](./examples/test_isolated_task.py)用标准库 `unittest` 检查启动助手的 11 项约定：临时目录、合成配置验证状态隔离，mock 端口、进程和 health 验证运行管理。不请求真实模型，也不检查金融答案准确度；平时跑任务无需运行它。两个脚本都是可选的，本地最短命令见前文。

## 1. 一次性准备固定模板

先激活已完成可编辑安装的环境，再从仓库根目录初始化：

```bash
conda activate py312
cd /Users/guoxing.lan/projects/github/nanobot
python tutorials_lgx/examples/launch_isolated_task.py init
```

初始化默认读取 `tutorials_lgx/.runtime/config.json`，提取已配置的模型、Provider 与网络设置，写入 `tutorials_lgx/.runtime/task_template/config.json`；角色文件来自仓库 `nanobot/templates/` 中的干净模板，并追加独立任务要求，不复制学习工作区中的记忆或已被学习改写的资料。它不覆盖已有任务模板。此步骤不调用模型，不改动原学习配置，也不影响已运行的学习 WebUI。

随后手动编辑模板中的固定资料：

| 文件 | 放什么 |
| --- | --- |
| `.runtime/task_template/workspace/AGENTS.md` | 任务规范、数据口径、工具使用与输出要求 |
| `.runtime/task_template/workspace/SOUL.md` | 金融 Agent 的固定角色与风格 |
| `.runtime/task_template/workspace/USER.md` | 必要的固定用户或业务背景；不放当次结论 |
| `.runtime/task_template/workspace/skills/` | 自行加入经过审核、版本固定的任务技能 |
| `.runtime/task_template/config.json` | 公司模型、接口、Key 或环境变量引用、温度与 token 预算 |

固定任务规则包括只使用本次描述与 `input/` 数据、将产物写到 `output/`。角色文件进入 system 上下文，不能代替工具权限限制，详见 [第 08 章](./08_角色与行为规范.md)。不要把旧 `memory/`、`.nanobot/`、cron、日志、历史报告或整个旧工作区复制进模板。每次启动只复制三份角色文件和技能，再生成新的工作区状态。

模板配置是一次快照，原学习配置后续改动不会自动同步；换模型或 Key 时修改任务模板配置。模板与运行目录都位于 Git 已忽略的 `.runtime/`，不要将其中的真实密钥或私有数据提交。

若终端存在 nanobot 配置覆盖环境变量，脚本会列出变量名并拒绝启动；按提示用 `unset 变量名` 取消覆盖，防止旧通道或 MCP 被环境设置重新启用。公司 Key 的普通 `${LGX_COMPANY_API_KEY}` 引用仍保留，不会打印变量值。

## 2. CLI：每次重新启动一项任务

不带外部数据时：

```bash
python tutorials_lgx/examples/launch_isolated_task.py cli \
  -m "任务：解释本次合成数据的营收增长率。上年1000万元，本年1200万元，已计算增长率为20%；给出公式和解释，将报告写入output/。"
```

带本次数据目录时，将路径替换为实际存在的目录：

```bash
python tutorials_lgx/examples/launch_isolated_task.py cli \
  --input /绝对路径/本次数据 \
  -m "任务：根据input/中的本次数据完成分析，标明数据时点与口径，将报告写入output/。"
```

`--input` 将目录内容复制到本次工作区的 `input/`，源目录不会成为 Agent 的默认工作目录。一次命令只提交本次任务的一份初始输入；模型可继续执行多次工具调用与模型循环，直到本次回合结束。实际启动会调用公司模型。默认未开放代码执行，数值可先在外部确定性计算，再作为本次输入；需要 Agent 调用 Python 时见第 5 节。

每次命令生成不同的任务目录与 session，CLI 结束即结束本次执行进程。会话仍保存，便于审计；下一次不会恢复它。需要重新运行同一输入时，也重新执行 helper，让它生成另一套实例，无需删除之前的记录。

仅准备配置、输入和目录，先检查隔离结果而不调用模型：

```bash
python tutorials_lgx/examples/launch_isolated_task.py cli \
  --prepare-only -m "检查准备步骤，本次不执行任务。"
```

`--prepare-only` 不启动 Agent 或 Gateway，会留下这次准备的目录；之后执行正常启动命令，会创建另一项新任务。

## 3. WebUI：每个实例只做一项任务

学习实例继续使用 `8766` / `18792`。独立任务使用另一对空闲端口：

```bash
python tutorials_lgx/examples/launch_isolated_task.py webui \
  --port 8767 --gateway-port 18793
```

需要文件时在启动命令末尾加 `--input /绝对路径/本次数据`。helper 为本次任务启动自己的 Gateway，验证实例身份后再打开原生 WebUI；若端口被占用则退出，不接入已有学习实例。两个端口必须都空闲，同时运行多项任务时为每项分配不同的端口对。

浏览器入口：[http://127.0.0.1:8767](http://127.0.0.1:8767)。按以下步骤操作：

1. 使用本次实例的默认工作区，保持 Restricted 权限，新建一条普通话题。
2. 输入本次任务描述，说明从 `input/` 读取材料、将报告写到 `output/`；等待模型与工具执行完成。
3. 保存需要的回答与报告，回到启动终端按 `Ctrl+C`，由 helper 清理自己启动的 Gateway。
4. 下一项任务重新执行 helper，生成新的实例；不要在旧实例中新建话题继续下一项任务。

此方案不依赖“临时聊天”：本次实例本来就没有旧历史与动态记忆，普通话题也方便保留执行记录。同一任务内补充信息或纠正输入可以继续这条话题；这属于本次任务的上下文。不要在 WebUI 中添加旧项目、切换到旧目录、开启 Full Access 或放宽工具配置，这些操作会改变本方案的隔离前提。

启动器自动打开网页，不显示猫形 Dock 图标；首次启动可能需要准备前端资源，构建提示不代表模型调用。需要紧急停止时，使用 helper 打印的本次路径，在另一个终端执行以下命令，替换三处占位路径：

```bash
python -m nanobot --home '/本次打印的home' gateway stop \
  --config '/本次打印的home/config.json' \
  --workspace '/本次打印的home/workspace'
```

停止命令的选择器必须对应本次实例，不要用学习实例的 `LGX_NANOBOT_HOME` 代替。查看端口占用见 [第 05 章](./05_常用命令速查.md#5-检查与排查)。

## 4. 文件保存在哪，如何复核

每次 helper 打印本次 home 与相关路径，目录结构如下：

```text
tutorials_lgx/.runtime/
├── task_template/                 # 固定配置、角色与技能，人工维护
│   ├── config.json
│   └── workspace/
└── task_runs/<uuid>/              # 每项任务各一份，不复用
    ├── config.json               # 本次配置，workspace显式指向本次目录
    ├── task.json                 # 任务标识、CLI输入与启动信息，不复制配置密钥
    ├── workspace/
    │   ├── AGENTS.md / SOUL.md / USER.md
    │   ├── skills/
    │   ├── input/                # 本次数据副本
    │   ├── output/               # 要求Agent生成的报告与结果
    │   ├── memory/               # 新建，起初没有旧任务内容
    │   └── .nanobot/             # 新的工作区标识等状态
    └── sessions/                 # 本次会话数据库等运行记录
```

运行时还可能在本次 home 下生成媒体、缓存、日志、WebUI 与网关状态；它们也不会复用学习实例或其他任务的目录。CLI / WebUI 的会话数据库用于回看消息与工具记录；CLI session 默认不会出现在 WebUI 侧栏，详见 [第 06 章](./06_工作区与会话存储.md)。`output/` 只有在任务要求与工具执行成功时才会产生报告，不等于自动导出的完整聊天；helper 不另外保存 CLI 的终端输出。

检查本次 `task.json`、配置中的 workspace、`input/` 快照与 `output/`，确认使用正确的模型、数据和规则。将业务需要的文件单独归档即可；保留旧任务目录不会使下一次自动加载它们，清空历史不是每次启动的必要步骤。

## 5. 隔离范围与工具选择

helper 从固定模板生成受限制的任务配置，启用范围限定到本次工作区的文件工具，禁用 shell、网页、MCP、CLI Apps、my、图像生成与语音能力。框架内置的会话、目标、子 Agent 或 cron 工具仍可能可用，但存储与执行属于本次实例；固定规则要求不创建后台任务，任务结束时停止本次进程。关闭 Dream、Heartbeat，将闲置压缩阈值设为 `0`。无需其他工具的首轮实验直接使用默认设置。该基线拒绝环境中额外安装的 `nanobot.tools` 插件，避免未审核工具绕过上述开关；遇到此错误时使用没有此类插件的环境。

| 状态 | 本方案的处理 |
| --- | --- |
| 旧消息、摘要与 Provider 会话续接状态 | 新 session、新会话存储、新进程 |
| 动态长期记忆、用户资料学习结果 | 新工作区，只从干净固定模板复制角色与技能 |
| 输入、报告、缓存、媒体与运行文件 | 新 home、新目录；文件工具限本次工作区 |
| 定时学习与后台任务 | Dream、Heartbeat、闲置压缩关闭，不复制旧 cron |
| 固定角色、模型设置与技能 | 来自同一人工维护模板，作为共同规则，不包含动态任务结论 |

运行中达到上下文预算时，压力压缩仍可能发生；它只整理本次 session 中的内容，下一次不会读取这个摘要。任务只有一份初始输入，也不代表只有一次模型请求。

需要 Python 计算时，显式加入 shell：

```bash
python tutorials_lgx/examples/launch_isolated_task.py cli \
  --allow-shell \
  -m "用Python计算合成数据：上年1000万元、本年1200万元的营收增长率，将代码与结果写入output/。"
```

WebUI 使用相同的 `--allow-shell` 参数。该选项针对本机 macOS，使用 `seatbelt` 限制 shell 子进程文件访问，并将当前 Python 环境作为只读依赖目录；本机为 `/Users/guoxing.lan/miniforge3/envs/py312`。不支持所需沙箱时应直接失败，不能改成无沙箱继续运行。

`seatbelt` 仍允许网络，不隔离共享数据库、远程 API、账户或外部服务状态，也不能撤回已发出的请求。若 shell 或以后新增的业务工具能够访问这些资源，应给每次任务独立的数据快照、命名空间与输出位置；首轮只读分析不要引入共享写入。Skills 的说明也不能扩大权限，含可执行脚本的技能需要按同样边界审核。

本方案保证的是在上述配置与使用步骤下，不复用其他任务的本地上下文和任务文件；它不是虚拟机或网络隔离容器。金融业务接入取数、数据库或交易工具时，需要再实现相应工具的权限、数据范围和输出隔离。

## 6. 临时聊天、SDK 与定时触发的关系

WebUI 新普通话题只分开聊天历史；新临时聊天还跳过 `MEMORY.md` 自动注入，但它们仍共用同一 Agent 的角色、用户资料、技能和文件。临时聊天的文件可被有权限的工具读取，所以仅靠这个开关不能满足本项目的完整任务隔离要求。

公开 SDK 的 `bot.run(..., ephemeral=True)` 使用非持久化会话策略，跳过普通长期记忆注入；它仍可能读取指定 session key 已有的历史副本，必须同时使用新 key，而且不隔离工作区与工具。后续服务化可以将本章的准备步骤接到 SDK 入口，再由业务程序保存结果，参考 [Python SDK](../docs/python-sdk.md)。当前 CLI `agent -m` 没有 `--ephemeral` / `--temporary` 参数。

当前内置 cron 绑定创建它的 session，重复执行默认继续该会话；每次 cron 的 `run_id` 不等于新的 session key。因此不要在同一 WebUI 话题中创建重复 cron 来代替本方案。正式定时触发可由外部调度器每次调用 helper 的 `cli` 入口，提供模板化任务描述与当期数据；届时再补充超时、结果校验、归档与失败通知。本次未创建定时任务，也未修改内置 cron 行为。
