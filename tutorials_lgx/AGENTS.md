# nanobot 学习协作准则

本目录用于在 `lgx_local1` 分支记录 nanobot 学习过程，并逐步构建金融垂域 Agent，也作为新同事的入门教材。源码章节重点解释实现、扩展和验证，操作教程应让有 Python 基础的新同事独立执行。此文件补充[仓库根目录规则](../AGENTS.md)，后续处理本目录的学习任务时先阅读本文件与 [README](./README.md)。

## 笔记约定

- 默认用中文，保留必要的英文术语、类名和配置字段。先给核心结论，再解释原因和例子；简洁通俗，但保留成立条件、能力边界和关键细节。
- 关键讨论结论及时更新到拥有该主题的笔记，补充 README 索引与进度；教程应可独立阅读，不要求读者翻聊天记录。总结学习内容，避免把无关项目话题或整段聊天转录混入教材。
- 一篇笔记围绕一个学习问题展开，通常包含：学习目标、核心解释、文档与源码入口、最小实验及命令、预期结果或实际结果。按内容需要组织，不必机械套用所有小节。
- 框架行为以当前检出源码为依据，教程和仓库文档用于导航。记录版本或提交基准；文档与代码不一致时，给出具体路径和差异，不凭印象补齐 API。
- 明确区分“源码已核对”“本地已运行”“待验证”和“金融场景设计建议”。未运行的命令不能写成已成功，模拟数据不能写成真实行情。
- 教学步骤与作者的本机运行记录分开；每个关键步骤说明预期结果和完成标准，个人路径、环境名称与历史报错标明适用范围。
- 链接到拥有该行为的源码和相关测试，引用类名或函数名；优先使用相对链接，避免复制大段上游文档或维护容易失效的行号。
- 新增笔记或示例时同步更新 README 索引和学习进度。后续结论变化时更新原笔记，并简要记录变化原因。
- Markdown 每段保持一行，不手动折行；表格用于对照，图用于解释链路，避免为了形式增加内容。

## 代码与实验约定

- 示例先求最小可理解、可运行，再考虑复用。文件和函数名说明用途，关键边界使用类型标注，注释解释设计原因、输入口径和框架接入点。
- Python 文件名和函数名使用英文 `snake_case`；Markdown 学习笔记继续使用中文文件名。
- Python 示例使用 `main()` 入口；异步调用正确等待，连接和任务正确清理。优先使用当前公开 SDK；需要内部接口时说明原因及其与当前源码版本的关联。
- 每个示例写明依赖、工作目录、配置前提、运行命令、预期输出和会产生的文件。默认命令从仓库根目录执行；占位符与配置片段必须显式标注。
- 环境准备提供清晰的主流程；激活环境后统一使用 `python -m pip` 和 `python -m nanobot`，可选环境和配置方案明确标注，避免新同事混用解释器或重复执行初始化。
- 笔记采用 `NN_中文主题.md` 命名；保留 `AGENTS.md`、`README.md` 等约定文件名；可运行代码按需放入 `examples/`，公开或合成的小样本按需放入 `fixtures/`。不预建没有内容的目录。
- 学习实例统一使用 `tutorials_lgx/.runtime/`，该目录不进入 Git。密钥默认通过环境变量引用；按已确认的本地学习方式，也可手动填写到被忽略的配置文件。提交的配置示例只含占位符；客户数据、账户信息和原始私有日志留在本地实验区。
- 每次实验记录使用的模型、输入、关键配置和观察结果。金融示例注明来源、数据时点、币种、单位、指标口径；计算交给确定性的代码，并提供可人工核对的小样本。

## 框架修改约定

- 先分析行为、状态归属和问题原因，再决定修改入口。金融能力优先通过 Tool、Skill、MCP 或外部服务接入；核心执行、会话和安全策略留在 Python 运行时。
- 学习材料和独立示例放在本目录；需要修改 `nanobot/` 时，只改与当前学习目标相关的拥有者，并在对应笔记说明修改目的、行为变化和验证方法。
- 遵循[开发导航](../.agent/navigation.md)和相关 `.agent/` 指南。先选覆盖真实使用路径的现有测试；新增测试须保护可到达、可观察的行为，不为纯笔记新增单元测试。
- 不运行 `ruff format`，不混入无关重构、格式化或依赖升级。保留用户已有改动，使用当前学习分支；提交、推送及发布按用户具体任务执行。
- 验证与变更范围匹配：笔记检查链接、命令/API 依据及 `git diff --check`；工具或运行时修改执行相关测试。验证结果明确列出实际运行项和未运行项。

## 三种 AGENTS.md 的区别

仓库根目录的 `AGENTS.md` 指导开发协作，本文件约定学习材料的写法；[nanobot/templates/AGENTS.md](../nanobot/templates/AGENTS.md)则是 nanobot 初始化工作区时使用的默认指令模板。后续金融 Agent 的运行指令应放在其有效项目工作区的 `AGENTS.md`，身份与用户资料属于 Agent 工作区的 `SOUL.md`、`USER.md`。

nanobot 的 `ContextBuilder` 不实现 Codex 的祖先目录指令继承链。本文件不会因为位于仓库子目录就自动成为 nanobot 的系统提示；学习协作规则与金融 Agent 运行提示需要分别维护。
